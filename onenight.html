ตัวแรก = root · ตัวถัดไปเทียบกับ node ปัจจุบัน: น้อยกว่าเลี้ยวซ้าย มากกว่าเลี้ยวขวา จนเจอช่องว่างแล้ววาง · เช็คตัวเองด้วย in-order (ซ้าย→root→ขวา) ต้องได้เรียงจากน้อยไปมาก · searchIter = เดินตามกฎเดียวกัน: เท่ากัน return · น้อยกว่าซ้าย · มากกว่าขวา · null คืน null

โจทย์ 4.3 — trace searchIter(35) บนต้นข้อ 4.1 + เขียนโค้ดจากความจำ

trace: cur = 25 → 35 > 25 → cur = 50 → 35 < 50 → cur = 35 → 35 == 35 → return 35 (เทียบ 3 ครั้ง)

TreeNode searchIter(int key) {
  TreeNode cur = root;
  while (cur != null) {
    if (key == cur.data) return cur;      // ← เจอ
    else if (key < cur.data) cur = cur.left;   // ← น้อยกว่าซ้าย
    else cur = cur.right;                      // ← มากกว่าขวา
  }
  return null; }

ปิดเฉลยแล้วเขียนใหม่จากความจำ 1 รอบ — ตรงนี้คือโค้ดที่ออกจริงปี 66 (เติม 1 บรรทัด)

Min Heap: insert (เคาะขึ้น) + delete min (เคาะลง)

🟥 ออกแน่ ทั้ง 66/67⏱ 40 นาทีเกณฑ์ผ่าน: ถูก 2 ใน 3
📗คอนเซปต์ 3 บรรทัด

สูตร: ลูกซ้าย = 2i+1, ลูกขวา = 2i+2, แม่ = (i−1)/2 · กฎเดียว: แม่ ≤ ลูก (min heap)
insert = วางท้ายแล้วเทียบกับแม่ ถ้าน้อยกว่าแม่ → สลับ ไต่ขึ้นจนหยุด (percolate up)
delete min = หยิบ root, ยกใบสุดท้ายมาแทน, สลับกับลูกที่เล็กกว่าลงไปจนถูกกฎ (percolate down)

ตัวอย่างที่ทำให้ดู — insert 4 ลง [2, 5, 7, 9, 6]

อธิบายทีละขั้น: ① วาง 4 ที่ "ช่องว่างแรก" ของ complete tree = index 5 (ลูกขวาของ 7) — ตำแหน่งนี้มีเสมอ ไม่ต้องหา ② แม่ของ idx 5 = (5−1)/2 = idx 1 คือ 5 → 4 < 5 ผิดกฎ min heap → สลับ ③ 4 ขึ้นไปอยู่ idx 1 → แม่ใหม่ = idx 0 คือ 2 → 4 > 2 ถูกกฎหยุด · ผลลัพธ์: [2, 4, 7, 9, 6, 5] สลับ 1 ครั้ง

BF = height(ซ้าย) − height(ขวา) (ใบ = 0, ช่องว่าง = −1) — อนุญาต −1, 0, +1 เท่านั้น

ดู 2 ก้าวสุดท้ายของเส้นทาง: ตรงกัน (LL/RR) = หมุนเดี่ยวสวนทาง · เลี้ยว (LR/RL) = หมุนคู่
LL → หมุนขวา · RR → หมุนซ้าย · LR → ซ้ายที่ลูกแล้วขวาที่ node · RL → ขวาที่ลูกแล้วซ้ายที่ node

ตัวอย่างที่ทำให้ดู — insert 30, 20, 10 (เคส LL)

อธิบายทีละขั้น: ① insert 30→20→10 แบบ BST ปกติ (10 ลงซ้ายสุด) · ② เดินขึ้นจาก 10: BF(20) = +1 ยังไหว, BF(30) = +2 ❌ — จุดหมุน = 30 ③ 2 ก้าวสุดท้ายคือ "ซ้าย-ซ้าย" (เคสนอก LL) → หมุนขวาที่ 30 รอบเดียว: 20 ยกขึ้น, 30 ถูกกดลงขวา ④ ทั้งต้น BF = 0 ทุก node · insert ต้องหมุนมากสุด 1 ชุดเสมอ (ทฤษฎีบท AVL)

โจทย์ให้ลอง:

โจทย์ 6.1 — insert 10, 20, 30 → พังที่ไหน เคสอะไร แล้ววาดหลังแก้

10 → 20 ขวา → 30 ขวาขวา → เดินขึ้น: 20 BF = −1 ok · 10 BF = −2 ❌ (พังที่ 10)
เส้นทาง 10→20→30 ขวา-ขวา = เคส RR → หมุนซ้ายที่ 10: 20 ขึ้นเป็น root, 10 ลงซ้าย

ผล: 20(10, 30) ✅ — ตรงข้ามกับตัวอย่างเป๊ะ (ซ้าย-ซ้าย ↔ ขวา-ขวา)

โจทย์ 6.2 — insert 30, 10, 20 → เคสอะไร แก้ยังไง?

30 → 10 ซ้าย → 20: ซ้ายของ 30, ขวาของ 10 → เดินขึ้น: 10 BF = −1 · 30 BF = +2 ❌ แต่ลูกซ้าย (10) BF = −1 (ถนัดขวา) → เส้นทาง ซ้าย-ขวา = เคส LR (เคสใน)

แก้ 2 รอบ: ① หมุนซ้ายที่ลูกซ้าย (10) → 20 ขึ้น 10 ลงซ้าย → เส้นทางกลายเป็น 30→20→10 ตรง ② หมุนขวาที่ 30 → 20 ขึ้น root
ผล: 20(10, 30) ✅ — จำง่าย: เคสใน = หมุนให้เส้นตรงก่อน แล้วจบแบบเคสนอก

โจทย์ 6.3 — จากต้น 20(10, 30) insert ต่อด้วย 25 → ต้องหมุนไหม?

25 > 20 → ขวาเจอ 30 → 25 < 30 → ซ้ายของ 30 (วางใบ)
เดินขึ้น: 25 ใบ · 30: BF = h(ซ้าย=1) − h(ขวา=−1) = +1 ok · 20: BF = 1 − 2 = −1 ok

ไม่พัง ไม่ต้องหมุน! ต้น: 20(10, 30(25, −)) — ข้อสอบชอบใส่ข้อแบบนี้ปนมาให้ระวัง ไม่ใช่ทุก insert ต้องหมุน

Kruskal MST: เรียงเส้น → รับ/ทิ้งด้วย Union-Find

🟥 ออกแน่ ปี 66⏱ 30 นาทีเกณฑ์ผ่าน: ตารางถูก 2 ใน 3
📗คอนเซปต์ 3 บรรทัด

เริ่มทุกจุดเป็นกลุ่มตัวเอง → เรียงเส้นจากถูกไปแพง → ไล่ดูทีละเส้น:
จบสองข้างคนละกลุ่ม (find ไม่เท่ากัน) = รับเส้น + union รวมกลุ่ม · กลุ่มเดียวกัน = ทิ้ง (รับแล้วสร้างวง!) · จบเมื่อได้ครบ V−1 เส้น

ตัวอย่างที่ทำให้ดู — จุด A, B, C: เส้น A–B (2), B–C (3), A–C (4)

อธิบายทีละขั้น: ① เริ่ม 3 จุดเป็น 3 กลุ่มโดด ๆ · ② เส้นถูกสุด A–B(2): find ต่างกัน → รับ แล้ว union เป็น {A,B} ③ เส้นถัดไป B–C(3): {A,B} กับ {C} ต่างกัน → รับ → จบเกณฑ์ (2 เส้น = V−1) · ④ A–C(4): find(A) = find(C) = หัวกลุ่มเดียวกัน → รับจะเกิดวง → ทิ้ง · MST = {A–B, B–C} รวม 5

โจทย์ 7.3 (concept) — ทำไมเส้นที่จบสองข้างกลุ่มเดียวกันถึงต้องทิ้ง?

เพราะถ้ารับ = เกิดวงวน (cycle) ทันที — MST ต้องเป็น tree: ต่อกันหมด + ไม่มีวง + ใช้แค่ V−1 เส้น
และ Union-Find จับได้เร็วมาก: แค่เทียบ find(u) == find(v) (หัวกลุ่มเดียวกันไหม) ใน ~O(1)

ช่อง 8

Dijkstra: trace ตาราง dist ทีละรอบ

🟥 ออกแน่ ทั้ง 66/67⏱ 40 นาทีเกณฑ์ผ่าน: trace ถูก 2 ใน 3
📗คอนเซปต์ 3 บรรทัด

dist[ต้นทาง] = 0 ที่เหลือ ∞ · วน: หยิบจุดที่ dist น้อยสุดจากคิว → ผ่อนทุกเส้นทางออกจากจุดนั้น: alt = dist[u] + w ถ้า alt < dist[v] → อัปเดต dist[v], prev[v]=u, ยัดคิวใหม่ · จบเมื่อคิวหมด · เขียนตารางไปทีละรอบ อย่าทำในหัว!

ตัวอย่างที่ทำให้ดู — A→B (2), A→C (5), B→C (1) จาก A

อธิบายทีละขั้น: ① dist = {A:0, B:∞, C:∞} · ② pop (0,A) ผ่อนเพื่อน: B = 0+2 = 2, C = 0+5 = 5 (ยังไม่รู้ว่าผ่าน B จะดีกว่า) ③ pop (2,B) — จุดน้อยสุดในคิว: ผ่อน C: alt = 2+1 = 3 < 5 → อัปเดต C = 3, prev[C] = B ④ pop (3,C) จบ · dist = {A:0, B:2, C:3} เส้นทางไป C = A→B→C — หัวใจของ Dijkstra: อย่าเชื่อเส้นตรง ให้เชื่อตัวเลขสะสม

โจทย์ให้ลอง:

โจทย์ 8.1 — A→B (4), A→C (1), C→B (1): dist สุดท้ายของ B?

pop A: B = 4, C = 1 · pop C (1): ผ่อน B: 1+1 = 2 < 4 → อัปเดต B = 2 ผ่าน C · pop B (2) จบ

B = 2, C = 1 · เส้นทางไป B = A→C→B — อ้อมผ่าน C ดีกว่า A→B ตรง (นี่คือหัวใจ Dijkstra: อย่าเชื่อเส้นตรง)

โจทย์ 8.2 — A→B (3), B→C (4), A→D (7), C→D (2): dist สุดท้ายทุกจุด?

pop A(0): B = 3, D = 7 · pop B(3): C = 3+4 = 7 · pop C(7): ผ่อน D: 7+2 = 9 ≥ 7 → ไม่อัปเดต (ข้าม!) · pop D(7) จบ

dist = {A:0, B:3, C:7, D:7} — จุดสำคัญ: เส้น C→D ไม่ช่วยอะไรเพราะ alt แพงกว่า dist เดิม (กรณี "ข้าม" ต้องโชว์ในตาราง ไม่งั้นโดนหัก)

โจทย์ 8.3 (concept) — ทำไม Dijkstra ใช้กับน้ำหนักติดลบไม่ได้?

เพราะ Dijkstra เป็น greedy: พอหยิบจุดที่ dist น้อยสุดออกจากคิว จะสมมติว่าค่านั้นสุดท้ายแล้วไม่กลับมาแก้อีก
น้ำหนักลบทำลายสมมติฐานนี้ — เดินอ้อมมาก่อน (มองว่าแพง) แล้วตามด้วยเส้นลบ อาจสั้นกว่าเส้นตรง → dist ที่ "ล็อก" ไปแล้วกลายเป็นผิด โดยอัลกอริทึมไม่ยอมแก้ให้

ช่อง 9

โค้ดที่ต้องเขียนจริง: Binary String (1 ห้ามติดกัน) + searchIter

🟥 แลปข้อเดียวของปี 67 + เติมโค้ดปี 66⏱ 30 นาทีเกณฑ์ผ่าน: เขียน Binary String ได้จากความจำ + searchIter ได้จากความจำ
📗คอนเซปต์ 2 บรรทัด

สร้าง string ทีละตำแหน่ง (recursion): วาง 0 ได้เสมอ · วาง 1 ได้เมื่อตัวก่อนไม่ใช่ 1 — กิ่งที่ผิดเงื่อนไขถูกตัดตั้งแต่ต้น
จำนวนคำตอบ = เลข Fibonacci: K=1→2, K=2→3, K=3→5, K=4→8

ตัวอย่างที่ทำให้ดู — K = 2 ทำมือ + เขียนโค้ด

อธิบายทีละขั้น: ① ทุกตำแหน่งเลือกได้ 2 ทาง (0 หรือ 1) — ยกเว้นถ้าตัวก่อนหน้าคือ 1 → ห้ามวาง 1 อีก ② โค้ด recursion จะ "โค้งซ้าย (วาง 0) ก่อนเสมอ" แล้วค่อยโค้งขวาถ้าได้ · ③ ถึงความยาว K = ถึงใบ → พิมพ์คำตอบ ④ จำนวนคำตอบ = เลข Fibonacci (K=1→2, K=2→3, K=3→5)

void gen(String s, int k, char last) {
  if (s.length() == k) { System.out.println(s); return; }
  gen(s + "0", k, '0');            // วาง 0 ได้เสมอ
  if (last != '1') gen(s + "1", k, '1');   // วาง 1 ได้เมื่อตัวก่อนไม่ใช่ 1
}
// เรียก: gen("", k, '0');

โจทย์ให้ลอง:

โจทย์ 9.1 — K = 3: ไล่คำตอบทั้งหมดด้วยมือ (จากต้นไม้ ช่วยให้ไม่หลง)

วาง 0 → "0": วาง 0 → "00": วาง 0 → 000 ✓, วาง 1 → 001 ✓ · "0" วาง 1 → "01": วาง 0 → 010 ✓ (วาง 1 = 011 ตัด)
วาง 1 → "1": ห้ามวาง 1 → วาง 0 → "10": วาง 0 → 100 ✓, วาง 1 → 101 ✓ (วาง 1 ต่อ 1 ตัด)

5 ตัว: 000, 001, 010, 100, 101 — ให้เขียนเป็นต้นไม้ 4 ชั้นในข้อสอบจะได้คะแนนขั้นตอนเต็ม

โจทย์ 9.2 — ปรับโค้ดให้กลายเป็นเงื่อนไข "0 ห้ามติดกัน" แทน

สลับบทบาท: วาง 1 ได้เสมอ · วาง 0 ได้เมื่อตัวก่อนไม่ใช่ 0:

gen(s + "1", k, '1');                    // วาง 1 ได้เสมอ
if (last != '0') gen(s + "0", k, '0');   // วาง 0 ได้เมื่อตัวก่อนไม่ใช่ 0

และเรียก gen("", k, '1') ก็ได้ (ตัวแรกเลือกอะไรก็ได้) — คำตอบ K=2 → 11, 10, 01 (3 ตัว)

โจทย์ 9.3 — K = 4 มีคำตอบกี่ตัว? (ไม่ต้องไล่ทุกตัว)

ใช้ Fibonacci: จำนวน(ยาว n) = จำนวน(ยาว n−1) + จำนวน(ยาว n−2)
(จบด้วย 0 → หน้าเป็นอะไรก็ได้ของ n−1 · จบด้วย 1 → หน้าต้องจบด้วย 0 ของ n−2)
2, 3, 5, 8, 13… → K = 4 มี 8 ตัว (คือ 2⁴−Fibonacci ที่ติดกัน: 0011, 0110, 0111, 1011, 1100, 1101, 1110, 1111 — ตัด 8 ตัว เหลือ 8 ตัว)

โจทย์ 9.4 — ปิดเฉลยแล้วเขียน searchIter + Binary String ใหม่จากความจำ (โค้ด 2 ตัวนี้ต้องออกไปแน่)

searchIter โครง: while (cur != null) → เท่ากัน return → น้อยซ้าย มากขวา → หลุด return null (เฉลยใน Drill 3 ข้อ 4.3)
Binary String โครง: if length==k print → gen(s+"0") เสมอ → if last!='1' gen(s+"1") (เฉลยด้านบน)

เขียนทั้ง 2 โดยไม่เปิดเฉลย = ผ่านเกณฑ์ช่องนี้ — โค้ดทั้งเว็บไม่ต้องจำอื่นอีกแล้ว
