Graph — จุดกับเส้น ที่ขยายไปได้ไกลถึง Google Maps

รีวิวรุ่นพี่ออก 2 ข้อยิบ ๆ: Kruskal หา MST แสดงขั้นตอน (Final 66) และ Dijkstra หา Shortest Path แสดงขั้นตอนพร้อมผลลัพธ์ (Final 66/67 — "โจทย์เป็นรูป แต่เปลี่ยนเลข") เราจะฝึก trace ทั้งสองแบบพร้อมตาราง ให้เขียนตามได้ในห้องสอบ

⭐ Kruskal trace + Union-Find ⭐ Dijkstra trace ตาราง dist ⭐ BFS/DFS พร้อม queue/stack

🌐 Graph คืออะไร

Graph คือ ADT ที่เก็บ "สิ่งของ + ความสัมพันธ์ระหว่างสิ่งของ" — G = (V, E): V (vertices/nodes) คือกลุ่มจุด, E (edges) คือกลุ่มเส้นเชื่อม โดยแต่ละเส้นเป็นคู่ (v, w) เหมือนโลกจริง: จุด = ห้องในบ้าน/เมือง/คน, เส้น = ประตู/ถนน/มิตรภาพ — อะไรก็แมปได้หมด:

  • ห้อง + ประตูต่อกัน → หาทางเดินจากห้องนอนไปครัว
  • เมือง + ถนน (มีระยะทาง) → GPS หาเส้นทางสั้นสุด ← คือ Dijkstra!
  • คน + การเป็นเพื่อนกัน → social network
  • สายไฟ + จุดต่อ → วงจรไฟฟ้า
📗ศัพท์พื้นฐานที่ออกเติมคำ
  • Undirected = เส้นสองทาง (มี (x,y) แปลว่ามี (y,x) ด้วย) · Directed = เส้นทางเดียว (เรียก edge ว่า arc — มีหัวลูกศร)
  • Weighted = ทุกเส้นมีตัวเลข (ระยะทาง/ค่าใช้จ่าย) ติดไปด้วย · ไม่มีน้ำหนัก = ทุกเส้นเท่ากัน
  • Loop = เส้นที่จาก x ไป x เอง · Multi-edge = จุดเดิมคู่เดิมมีหลายเส้น · กราฟที่ไม่มีทั้งสองอย่างเรียก simple graph
  • Adjacent: w adjacent กับ v ถ้ามีเส้น (v, w) — "ติดกัน"
  • Degree = จำนวนเส้นที่แตะ node นั้น (undirected) · directed แยก in-degree (ลูกศรเข้า) / out-degree (ลูกศรออก)
  • Sparse = เส้นน้อย (|E| = O(|V|)) · Dense = เส้นเยอะ (|E| = O(|V|²))

🧩 ชนิดกราฟพิเศษ

🛤️ Path, Cycle, Connected Component

📗ศัพท์เส้นทาง
  • Path = ลำดับจุดที่เดินต่อกันได้ด้วยเส้น · length ของ path = จำนวนเส้น (เดินจากตัวเองไปตัวเอง = 0)
  • Simple path = ไม่แวะจุดไหนซ้ำ
  • Cycle = path ที่ออกจากจุดแล้ว "วนกลับมาจบที่จุดเดิม" (ยาว ≥ 2 จุด, ไม่ย้อนเส้นเดิม) · simple cycle = ไม่มีจุดซ้ำนอกจากจุดเริ่ม-จบ
  • DAG = Directed Acyclic Graph — กราฟมีทิศที่ไม่มีวงวน (ใช้ทำ schedule/timeline)
  • Connected component = ก้อนที่จุดภายใน "ไปหากันได้หมด" และใหญ่สุดแล้ว (undirected) — กราฟถูกแบ่งเป็นก้อน ๆ ไม่ซ้ำกัน
  • Forest = กราฟที่แต่ละ component เป็น tree (ไม่มีวง) · Tree = connected + ไม่มี cycle (undirected)
📝Subgraph (เคยออกในสไลด์ MIT)

H = (V′, E′) เป็น subgraph ของ G = (V, E) ต่อเมื่อ V′ ⊆ V และ E′ ⊆ E — ระวังกับดัก: "หยิบเส้นมาแล้วแต่จุดปลายเส้นไม่อยู่ใน V′" = ไม่ใช่ subgraph · "ใช้เส้นที่ไม่มีใน G" = ไม่ใช่เช่นกัน

🌊 BFS — Breadth-First Search (กว้างก่อน ใช้คิว)

เดินสำรวจกราฟแบบ "ระดับ" เหมือนกระดานหยดน้ำ: สำรวจจุดใกล้ ๆ ทั้งหมดก่อน แล้วค่อยขยายวงออกไป — ใช้ Queue (FIFO) จุดแต่ละจุดมี 3 สถานะ: unvisited → discovered (ต่อคิวแล้ว) → explored (ดึงออกและประมวลผลแล้ว)

💡เปรียบเทียบ

BFS = ข่าวลือแบบวงขยาย: คุณบอกเพื่อนสนิททุกคน (ระดับ 1) แล้วเพื่อนสนิทแต่ละคนไปบอกเพื่อนของเขา (ระดับ 2) … ข่าวลามเป็นวงกลม DFS = ไต่ถ้ำ: เดินลึกสุดทางก่อน ตันค่อยย้อนกลับไปแยกทางอื่น

Trace BFS จาก A (เรียงเพื่อนบ้านตามตัวอักษร)

⚠️กุญแจสำคัญ: mark "discovered" ตอน enqueue

สังเกต step 5: E ไม่ enqueue H อีก เพราะ H โดน mark ตั้งแต่ตอน D ส่งเข้าคิว — เช็คก่อน enqueue ทุกครั้ง ไม่งั้นจุดเดียวจะเข้าคิวซ้ำหลายรอบ ผล trace พังทันที (คำถามสไลด์ "What if enqueue(B)?" = ถ้าไม่เช็ค ก็จะวนไม่รู้จบ!)

void bfs() {
  Queue<Vertex> q;
  for all v in V: d[v] = ∞      // ทุกจุด unvisited
  q.enqueue(startVertex);
  d[startVertex] = 0;            // จุดเริ่ม: ระยะ 0
  while (!q.isEmpty()) {
    u = q.dequeue();
    for each w adjacent to u {
      if (d[w] == ∞) {           // ยังไม่เคยเจอ
        d[w] = d[u] + 1;         // ระยะ = ระยะพ่อ + 1 → BFS ให้ "จำนวนเส้นน้อยสุด" ในกราฟไม่มีน้ำหนักฟรี ๆ!
        path[w] = u;             // จำว่ามาจากไหน (ย้อนเส้นทางได้)
        q.enqueue(w);
      }
    }
  }
}

🕳️ DFS — Depth-First Search (ลึกก่อน ใช้สแตก/recursion)

trace DFS แบบ recursive จาก A (เลือกเพื่อนบ้านตัวอักษรแรกก่อนเสมอ) — "call stack" คือสายโซ่ recursion ที่ลึกอยู่:

stepสิ่งที่เกิดCall stack (ลึกสุดขวา)DFS order สะสม
1dfs(A) → เพื่อนตัวแรกคือ B → ดำดิ่ง(A B)A
2dfs(B) → D (A เยี่ยมแล้ว)(A B D)A, B
3dfs(D) → H(A B D H)A, B, D, H
4dfs(H) → D แล้ว แต่ E ยังไม่เคยเหยียบ → เข้า E(A B D H E)A, B, D, H, E
5dfs(E) ตัน (B, H หมด) → ย้อนกลับ (backtrack) ทีละชั้นจนถึง A(A)…E
6กลับที่ A → เหลือ C → dfs(C) → F → (H แล้ว) → G → ครบทุกจุด()A, B, D, H, E, C, F, G ✅
// แบบ recursive — เขียนสั้นและสวยที่สุด
void dfs(Vertex v) {
  if (v.visited) return;
  v.visited = true;                  // mark ตอน "เหยียบ"
  // process v …
  for each w adjacent to v
    if (!w.visited) dfs(w);           // ดำดิ่งลงไปก่อน ย้อนกลับ (backtrack) เองโดย call stack
}

// แบบ iterative ด้วยสแตก (pre-order)
void dfsIter() {
  Stack<Vertex> s;  s.push(startVertex);  startVertex.visited = true;
  while (!s.isEmpty()) {
    u = s.pop();
    // process u …
    for each w adjacent to u
      if (!w.visited) { w.visited = true; s.push(w); }
  }
}
💡BFS vs DFS — หัวใจที่ออกเทียบบ่อย

โครงเดียวกันหมด ต่างกันแค่ โครงสร้างข้อมูล: BFS ใช้ Queue (เอาตัวเก่าสุดออกก่อน = วงกว้าง) DFS ใช้ Stack/recursive (เอาตัวใหม่สุดออกก่อน = วงลึก) · ทั้งคู่ O(V + E) · BFS ได้เส้นทาง "เส้นน้อยสุด" ในกราฟไม่มีน้ำหนักฟรี ๆ จาก d[] และ path[]

🌲 MST — Minimum Spanning Tree

📗ศัพท์ที่ต้องเข้าใจก่อน
  • Spanning tree ของกราฟ connected, undirected = subgraph ที่ (1) มี จุดครบทุกจุด (2) ต่อถึงกันหมด (3) ไม่มีวงวน → เส้นพอดี V − 1 เส้น (หนึ่งกราฟมี spanning tree ได้หลายแบบ)
  • MST = spanning tree ที่ "ผลรวมน้ำหนักเส้นน้อยสุด" — ใช้จริง: ต่อสายไฟทั้งหมู่บ้านด้วยลวดสั้นสุด, วางท่อ/ถนนเชื่อมทุกจุดถูกสุด
  • ถ้าน้ำหนักทุกเส้นต่างกันหมด → MST จะมีแบบเดียว (ถ้ามีเส้นน้ำหนักซ้ำอาจมีหลาย MST)

Prim's Algorithm — "โตต้นไม้จาก 1 จุด"

เริ่มจากจุดไหนก็ได้ แล้ววนซ้ำ: เลือก เส้นที่ถูกสุดที่ยื่นออกนอกต้นไม้ (ปลายหนึ่งในต้นไม้ อีกปลายอยู่นอก) ดึงเข้ามา จนครบทุกจุด — เหมือนหยอดกระดุมเม็ดแรกแล้วค่อย ๆ ดึงกระดุมใกล้สุดทีละเม็ด · ใช้ priority queue เก็บ key[v] = เส้นถูกสุดที่พา v เข้าต้นไม้ → O(E log V)

🗺️ Dijkstra — หาเส้นทาง "ถูกสุด" จากจุดเดียวไปทุกจุด

Single-Source Shortest Path: ให้จุดเริ่ม s หาเส้นทางน้ำหนักรวมน้อยสุดไป "ทุกจุด" ที่ไปถึง (ข้อบังคับ: น้ำหนักไม่ติดลบ) — คือหัวใจของ GPS/Google Maps ผลลัพธ์ 2 อย่าง: dist[v] = ระยะสั้นสุดถึง v, prev[v] = จุดก่อนหน้า (ย้อนทางได้)

📗หัวใจ: Relaxation (คลายเส้น)

"ลองเดินผ่าน u ไปหา v จะดีกว่าเดิมไหม?" — alt = dist[u] + w(u,v) ถ้า alt < dist[v] → อัปเดต dist[v] = alt, prev[v] = u ทำกับทุกเส้นของจุดที่ "ดีที่สุดในคิว" ที่เพิ่งหยิบออก · greedy: ทุกครั้งหยิบจุดที่ dist น้อยสุดจากคิวมาปลดล็อก (จุดนั้นเรามั่นใจสุดแล้ว)

"stale" คือของเก่าจาก lazy queue — พอดึงมาเจอว่า dist ปัจจุบันดีกว่าแล้ว ก็ข้าม (ดูโค้ดข้างล่าง)

Lazy Queue — เทคนิคเขียนจริงเมื่อ PQ ไม่มี decreaseKey

push(pq, 0, s)
while (!pq.empty()) {
  (du, u) = extractMin(pq)
  if (du > dist[u]) continue;   // ของเก่า (เคยเจอทางสั้นกว่าแล้ว) → ทิ้งเลย นี่คือ "visited check" ของ lazy
  for each edge (u, v, w):
    if (du + w < dist[v]) {
      dist[v] = du + w;
      prev[v] = u;
      push(pq, dist[v], v);      // แทรกของใหม่เพิ่มเข้าไปเฉย ๆ ไม่ต้องไปแก้ของเก่า
    }
}
// อยากได้แค่ s→t: เพิ่ม if (u == t) break; ตอน pop (early exit)

Complexity: insert เกิดได้มากสุด O(E) ครั้ง → O(E log V) (โดยรวมเต็ม ๆ O(|V| + |E| log |V|)) — Prim แบบ lazy ก็ O(E log V) เท่ากัน

⚠️MST ≠ เส้นทางสั้นสุด!

คำถามคลาสสิก: "MST ใช้เป็นเส้นทางสั้นสุดได้ไหม?" — ไม่ได้! MST มองภาพรวม (ผลรวมเส้นน้อยสุด) แต่ Dijkstra มองรายจุด (จาก s ไปแต่ละจุดสั้นสุด) — เส้นทางใน MST ไป A→B อาจแย่กว่าเส้นตรงที่ไม่ได้อยู่ใน MST · ตารางเทียบตรง ๆ:

Prim (MST)Dijkstra (Shortest Path)

🤝 Union-Find — ตามว่า "ใครอยู่กลุ่มเดียวกัน"

โครงสร้างจัดการ กลุ่มที่ไม่ซ้อนกัน (disjoint sets) ด้วย 2 คำสั่ง:

  • find(x) — คืน "หัวหน้ากลุ่ม" (root) ของ x → สองตัวอยู่กลุ่มเดียวกัน ⟺ find เท่ากัน
  • union(a, b) — รวมกลุ่มของ a กับ b (ถ้าคนละกลุ่ม)

แนวคิด: จำ "parent" ของแต่ละตัวใน array — ตัวที่ parent ชี้ตัวเอง = หัวหน้า · ตรวจว่าจุด 2 จุดต่อถึงกันในกราฟหรือยัง ก็แค่เทียบหัวหน้า! (นี่คือเครื่องมือกันวงวนของ Kruskal)

📝ตัวอย่างจากสไลด์: union by rank

เริ่ม 5 ตัวล้วนเป็นกลุ่มตัวเอง (rank ทุกตัว = 0) · ทำ union(0,1), union(1,2), union(2,3)

เฉลยทีละขั้น
  1. union(0,1): find(0)=0 (rank 0), find(1)=1 (rank 0) → เท่ากัน เลือก 1 เป็นหัว: parent[0]=1, rank[1] = 1
  2. union(1,2): find(1)=1 (rank 1), find(2)=2 (rank 0) → rank 1 > rank 0 → parent[2]=1 (ต้นสั้นติดใต้ต้นสูง)
  3. union(2,3): find(2)=1 (rank 1), find(3)=3 (rank 0) → parent[3]=1

ผล: {0,1,2,3} อยู่ใต้หัว 1 และ {4} อยู่โดด — 2 components

Path compression: ตอน find วิ่งผ่านตัวไหน "รีด" ให้ตัวนั้นชี้ตรงหัวเลย (parent[x] = find(parent[x)) — ครั้งหน้า find เร็วสุด ๆ ทั้งสองเทคนิครวมกัน → find/union ≈ O(α(n)) ≈ O(1) (α = ฟังก์ชันกลับด้าว Acker­mann โตช้ากว่า log อีก)

public int find(int x) {
  if (parent[x] != x)
    parent[x] = find(parent[x]);    // path compression — รีดทางให้ชี้ตรง root
  return parent[x];
}
public void union(int a, int b) {
  int rootA = find(a), rootB = find(b);
  if (rootA == rootB) return;        // กลุ่มเดียวกันแล้ว — รวมไม่ได้ (สำคัญมากกับ Kruskal!)
  if (rank[rootA] < rank[rootB])      parent[rootA] = rootB;   // ต้นสั้นขึ้นไปใต้ต้นสูง
  else if (rank[rootA] > rank[rootB]) parent[rootB] = rootA;
  else { parent[rootB] = rootA; rank[rootA]++; }               // เท่ากัน: เลือกได้ + เพิ่ม rank
}

🌉 Kruskal's Algorithm — เรียงเส้นถูกสุด แล้วเลือกทีละเส้น (ออกสอบ!)

ต่างจาก Prim ที่โตทีละต้น — Kruskal เริ่มจาก "ป่าของจุดโดด" แล้วคัดเส้นจากถูกสุดไปแพงสุด: เจอเส้นที่ เชื่อมสองกลุ่มที่ยังแยกกัน → รับเลย · เจอเส้นที่จบสองข้างอยู่กลุ่มเดียวกัน (จะสร้างวง) → ทิ้ง ใช้ Union-Find เป็นเครื่องตรวจ "กลุ่มเดียวกันไหม" — ต้นทุนหลักคือการเรียงเส้น O(E log E)
