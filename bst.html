BST — ต้นไม้ที่จัดให้ "เลขน้อยซ้าย มากขวา"

รีวิวรุ่นพี่มีชัด ๆ ว่าออก 2 แนว: (1) เติมโค้ดที่หาย 1 บรรทัด ⇒ searchIter(int key) และ (2) ให้ชุดตัวเลข แสดงขั้นตอนการสร้าง BST พร้อมผลลัพธ์สุดท้าย — แถมรุ่นพี่บอกว่าข้อสอบ "มีให้วาด tree ไปแล้วครึ่งนึง" หน้านี้ฝึกวาดจนมือเย็น

⭐ เติมโค้ด searchIter ⭐ trace สร้าง BST ⭐ delete 3 เคส ⭐ in-order = เรียงแล้ว

🌳 Tree คืออะไร + ศัพท์ที่ต้องออกเวลาเติมคำ

Tree คือ ADT ที่ข้อมูล "โยงกันแบบกิ่งก้าน" — แตกต่างจาก array/linked list ที่เป็นเส้นตรง (linear): tree แตกทางได้ จึงหาข้อมูลได้เร็วขึ้นด้วยการ "ตัดสินใจเลือกทาง" ทุกชั้น (เหมือนเล่น 20 questions: หนึ่งคำถามตัดความเป็นไปได้ครึ่งหนึ่ง)

💡เปรียบเทียบให้จำขึ้นใจ

นึกถึง แผนผังองค์กร: ผู้จัดการใหญ่ = root, ทีมใต้สังกัด = subtree, พนักงานที่ไม่มีใครใต้บังคับบัญชา = leaf, "ระดับชั้น" จากบอส = depth — ทุกศัพท์แมปกับที่ทำงานได้หมด

⚖️ Balanced vs Deformed — หัวใจของความเร็ว

🧱 เก็บ tree ไว้ในโค้ดยังไง

  • แบบ heap เราใช้ array (ได้เพราะ complete tree) — แต่ tree ทั่วไปเอียง ๆ array จะมีรูโหล ๆ เปลืองมาก
  • ปกติจึงใช้ node + references เหมือน linked list แต่กิ่งก้านมากกว่า:

🚶 Traversal — เดินเก็บทุก node ให้ครบ (3 ลำดับ)

การเดิน tree คือการ "ค้นพบและจัดการ" ข้อมูลทุกตัว โดยแต่ละ node มี 3 สถานะ: undiscovered → discovered → processed (binary tree มีลำดับเดิน 3 แบบ — ต่างกันแค่จุดที่ "จัดการ node กลาง" เท่านั้น!):

ลำดับสูตรจำเมื่อไรจัดการ node กลางใช้ทำอะไร
Pre-orderRoot → Left → Rightก่อนลูกcopy tree, เขียน prefix expression
In-orderLeft → Root → Rightระหว่างลูกสองฝั่งดึงข้อมูลจาก BST ออกมา "เรียงแล้ว"!
Post-orderLeft → Right → Rootหลังลูกลบ tree ทั้งต้น (ต้องลบลูกก่อนแม่), หาขนาด subtree
🚶เดินแบบ in-order ทีละก้าว

ให้ทำ subtree: ลูกซ้ายก่อน → ตัวเอง → ลูกขวา
จาก tree ข้างบน: (20,30,40) → 60 → (70,80,90)
subtree 30: 20 → 30 → 40 · subtree 80: 70 → 80 → 90
รวม: 20, 30, 40, 60, 70, 80, 90 — เรียงจากน้อยไปมากเลย! (ใช้เช็ค BST ในข้อสอบได้: in-order แล้วไม่เรียง = ไม่ใช่ BST)

🚶เดินแบบ pre-order / post-order

Pre-order: 60 → (30 → 20 → 40) → (80 → 70 → 90) = 60, 30, 20, 40, 80, 70, 90 (root มาก่อนเสมอ — ใช้วาด tree จากลิสต์ได้)
Post-order: (20 → 40 → 30) → (70 → 90 → 80) → 60 = 20, 40, 30, 70, 90, 80, 60 (root มาท้ายสุด — ลบ tree จากใบขึ้น root)

// โค้ดจริง 3 แบบ — ต่างกันแค่ตำแหน่งบรรทัด print!
void printPreOrder(TreeNode node)  { if(node==null) return;
  System.out.println(node.data); printPreOrder(node.left); printPreOrder(node.right); }
void printInOrder(TreeNode node)   { if(node==null) return;
  printInOrder(node.left); System.out.println(node.data); printInOrder(node.right); }
void printPostOrder(TreeNode node) { if(node==null) return;
  printPostOrder(node.left); printPostOrder(node.right); System.out.println(node.data); }
// เรียกใช้: printInOrder(root); — ส่ง root เข้าไปเป็นพารามิเตอร์เพื่อ recursion
📗พื้นฐาน: ทำไมใช้ recursion ได้สวยงาม

ทุก subtree ก็คือ "tree" ต้นเล็ก — ปัญหาเดิมเป๊ะ แค่เล็กลง = โครงสร้าง recursive ตามธรรมชาติ ฐานหยุดคือ node == null (กิ่งโล้น ไม่มีอะไรเดิน) — แนวคิดเดียวกันจะโผล่อีกทั้ง BST delete, AVL, Red-Black, Dijkstra recursion และโจทย์ Binary String ในหน้าแนวข้อสอบ!

🔍 BST Property — กฎทองเส้นเดียว

📗กฎของ Binary Search Tree

ที่ ทุก node (ไม่ใช่แค่ root!): ค่าใน node ≥ ค่าลูกซ้ายทั้งฝั่ง และ ≤ ค่าลูกขวาทั้งฝั่ง หรือพูดง่าย ๆ "ซ้ายน้อยกว่าแม่ ขวามากกว่าแม่ — บังคับทุก node"

กฎนี้ทำให้การค้นเหมือน binary search: เทียบค่าที่ต้องการกับ node ปัจจุบัน → น้อยกว่าไปซ้าย มากกว่าไปขวา → ตัดทิ้งครึ่งหนึ่งของ tree ทุกชั้น → balanced จะเจอใน O(log n) ชั้น แต่ถ้า tree เอียงจะกลายเป็น O(n)

💡เปรียบเทียบ

เหมือนเดาตัวเลข 1–1000 แบบ "มากกว่า 500 ไหม?" ทีละครึ่ง — BST คือการวางคำถามตัดครึ่งไว้เป็นโครงสร้างข้อมูลเลย (ส่วน heap ไม่ใช่: heap รู้แค่ว่า root เล็กสุด แต่ค้นค่าอื่นต้องไล่ทั้งต้น! — คำถามชวนเทียบที่ออกบ่อย)

💻 search / searchIter / insert — โค้ดที่เติมในข้อสอบ

search แบบ recursive (จากสไลด์)

// แบบเรียกสวย: search(d) → searchRecurse(d, root)
TreeNode searchRecurse(int d, TreeNode node) {
  if (node == null) return null;      // วิ่งหลุดใบ = ไม่มีข้อมูลนี้
  if (d == node.data) return node;   // เจอแล้ว
  if (d < node.data) return searchRecurse(d, node.left);   // น้อยกว่า → ซ้าย
  return searchRecurse(d, node.right);                      // มากกว่า → ขวา
}
📝ออกสอบจริง (Final 66): เติมโค้ด 1 บรรทัด ⇒ searchIter(int key)

โจทย์ให้โครงมาครึ่งหนึ่ง หายไปบรรทัดเดียว — เฉลยเต็มที่ควรเขียน:

เฉลย searchIter แบบเต็ม
TreeNode searchIter(int key) {
  TreeNode cur = root;                     // เริ่มที่ root
  while (cur != null) {                    // วิ่งจนหลุดใบ
    if (key == cur.data) return cur;      // ← จุดที่โจทย์มักให้เติม: เจอ = คืน node
    else if (key < cur.data) cur = cur.left;   // น้อยกว่า → เลี้ยวซ้าย
    else                     cur = cur.right;  // มากกว่า → เลี้ยวขวา
  }
  return null;                             // หลุดใบโดยไม่เจอ
}

ถ้าโจทย์เติมแค่ 1 บรรทัด มักเป็น cur = cur.left; / cur = cur.right; (เลี้ยวตาม BST property) หรือ if (key == cur.data) return cur; — จำโครง "เดินตามกฎซ้าย-ขวาจน null" ให้ได้

insert แบบ iterative (มีช่องว่าง your code 1/2 ตามสไลด์)

void insert(int d) {
  if (root == null) { root = new TreeNode(d); return; }  // ต้นเปล่า → ตัวแรกเป็น root
  TreeNode current = root;
  while (current != null) {
    if (d < current.data) {
      if (current.left != null)  current = current.left;      // มีที่วิ่งต่อซ้าย
      else { current.left = new TreeNode(d);              /* your code 1: ซ้ายว่าง → สร้าง node ใหม่ผูกซ้าย */
             current.left.parent = current; return; }
    } else {
      if (current.right != null) current = current.right;     /* your code 2: มีที่วิ่งต่อขวา */
      else { current.right = new TreeNode(d);
             current.right.parent = current; return; }
    }
  }
}

เห็นไหมว่า insert = "search หาช่องว่างแล้ววาง" — ต้นทางเดียวกับ search เป๊ะ จึงรันเวลาเท่ากัน O(log n) ถ้า balanced, O(n) ถ้าเอียง

🗑️ delete — 3 เคสที่ต้องเล่าให้ได้

ลบ node จาก BST ต้องรักษากฎ "ซ้ายน้อยขวามาก" ไว้ แบ่งเป็น 3 เคสตามจำนวนลูก:

เคส 1: ลบใบ (ไม่มีลูก)ง่ายสุด — ตัด node ออก ตั้ง pointer ของแม่ชี้ null (ไม่กระทบใคร)
เคส 2: มีลูกเดียวยกลูกขึ้นมาแทนที่ตัวเอง — แม่ของเราเลี้ยวไปหาลูกของเราตรง ๆ (เหมือนคนลาออก ให้ลูกน้องรับช่วงตำแหน่ง)
เคส 3: มีสองลูก (ยาก!)หา "ตัวแทน" มานั่งตำแหน่งเดิม: ค่ามากสุดของ subtree ซ้าย (in-order predecessor) หรือ ค่าน้อยสุดของ subtree ขวา (in-order successor) — สองตัวนี้เป็นค่าที่ "อยู่ติดขอบ" พอดี จึงขยับมาแทนได้โดยกฎ BST ไม่พัง แล้วลบตัวแทนออกจากที่เดิม (ตัวแทนมีลูกมากสุด 1 คน → กลับไปเคส 1 หรือ 2)

โค้ด delete (โครงจากสไลด์ — ใช้ parent pointer)

void delete(int d, TreeNode node) {
  if (node == null) return;              // ไม่เจอ
  if (d < node.data) { delete(d, node.left); }    // หาทางซ้าย
  else if (d > node.data) { delete(d, node.right); }  // หาทางขวา
  else {  // เจอ node ที่มีค่า == d
    if (node.left == null || node.right == null) {   // เคส 1-2: ลูก 0 หรือ 1 คน
      TreeNode q = (node.left == null) ? node.right : node.left;  // q = ลูกที่มีอยู่ (อาจ null)
      if (node.parent != null) {
        if (node.parent.left == node) node.parent.left = q;   // แม่เลี้ยวไปหา q แทนเรา
        else                          node.parent.right = q;
        if (q != null) q.parent = node.parent;  // อัปเดต parent ของ q ด้วย
      } else root = q;                         // เราคือ root → q ขึ้นเป็น root
    } else {   // เคส 3: สองลูก
      TreeNode q = findMaxFrom(node.left);    // ตัวแทน = predecessor
      delete(q.data, node.left);               // ลบตัวแทนออกจากที่เดิมก่อน (เคส 1-2 เท่านั้น)
      if (node.parent == null) root = q;      // ต่อ parent เดิมเข้าหาตัวแทน
      else if (node.parent.left == node) node.parent.left = q;
      else                               node.parent.right = q;
      q.left = node.left;   if (q.left != null)  q.left.parent = q;   // รับลูกซ้าย
      q.right = node.right; if (q.right != null) q.right.parent = q;  // รับลูกขวา
      q.parent = node.parent;
    }
  }
}
// อีกแนว (สั้นกว่า): swap ค่าของ successor เข้ามาแทนใน node นี้ แล้ว delete ตัว successor จริง ๆ ใน subtree ขวา

🏅 Example Challenge จากสไลด์ (แนวข้อสอบสายโค้ด)

📝โจทย์ 1: findMax จาก BST

กำหนด BST สร้างจาก {5, 3, 8, 2, 4, 7, 9} — เขียน findMax(bst) คืนค่ามากสุด (เฉลย 9)

เฉลย

กฎของ BST บอกว่า "ค่ามากสุด = node ที่วิ่งขวาไปสุด" (แค่ไหนก็ขวาจนหลุด) — ไม่ต้อง traverse ทั้งต้นเลย:

private static int findMax(MyBST_Basic bst) {
  Node node = bst.root;
  if (node == null) return -1;          // tree ว่าง
  while (node.right != null)            // ลื่นไปทางขวาจนสุด
    node = node.right;
  return node.val;
}

O(h) — balanced คือ O(log n) (เช่นเดียวกัน findMin = วิ่งซ้ายสุด)

📝โจทย์ 2: rangeSumBST(node, low, high) — ผลรวมค่าในช่วง [4..8] (เฉลย 24)
เฉลยทีละบรรทัด + trace ตามสไลด์
private static int rangeSumBST(Node node, int low, int high) {
  if (node == null)   return 0;                        /*A*/
  if (node.val < low)  return rangeSumBST(node.right, low, high); /*B*/ ตัวนี้เล็กเกิน → ฝั่งซ้ายเล็กกว่าอีก ตัดทิ้ง!
  if (node.val > high) return rangeSumBST(node.left, low, high);  /*C*/ ตัวนี้ใหญ่เกิน → ฝั่งขวาใหญ่กว่าอีก ตัดทิ้ง!
  return node.val + rangeSumBST(node.left, low, high)              /*D*/ อยู่ในช่วง → นับ + สองฝั่งยังอาจมีของในช่วง
                  + rangeSumBST(node.right, low, high);
}

trace กับ BST {5,3,8,2,4,7,9} เรียก rangeSumBST(root,4,8) — ตามขั้นที่สไลด์เฉลย:

  1. node 5 → อยู่ในช่วง (เคส D) → 5 + sum(ซ้าย=3) + sum(ขวา=8)
  2. sum(3): 3 < low=4 (เคส B) → วิ่งขวาเท่านั้น → rangeSumBST(4, 4, 8)
  3. node 4 → อยู่ในช่วง (เคส D) → 4 + sum(null) + sum(null) = 4
  4. sum(8): อยู่ในช่วง (เคส D) → 8 + sum(7) + sum(9)
  5. node 7 → 7 + 0 + 0 = 7
  6. node 9 → 9 > high=8 (เคส C) → วิ่งซ้าย = null → 0

รวม: 4 + 5 + (7 + 8 + 0) = 24 ✅ — จุดขายของโค้ดนี้คือใช้ BST property "ตัดทาง" (B, C) เหมือน search แทนการไล่ทั้งต้น
