⏱️ ตาราง Big-O รวมทุกบท (ท่องก่อนเข้าห้องสอบ)

💡อ่าน Big-O อย่างไรให้เป็นเรื่องง่าย

Big-O คือ "อัตราการโตของเวลา เมื่อข้อมูลเยอะขึ้น" — เปรียบเหมือนการหาชื่อคนในสมุดโทรศัพท์: ถ้าเปิดทีละหน้าจากหน้าแรก = O(n) เปิดครึ่งเล่มทิ้งครึ่งเล่มไปเรื่อย ๆ = O(log n) (1,000 รายชื่อใช้แค่ ~10 ครั้ง, 1,000,000 รายชื่อใช้แค่ ~20 ครั้ง — ข้อมูลโต 100 เท่า งานโตแค่ 2 เท่า!) ส่วน O(n²) คือเทียบทุกคู่ ข้อมูลโต 10 เท่า งานโต 100 เท่า ถึงเวลาสอบเราเลยใช้ Big-O เป็น "คะแนนความเร็ว"

✍️ เทคนิคทำข้อสอบ DSA

โจทย์ trace — วาดไปทีละสเต็ป อย่าทำในหัวแทบทุกข้อ trace (insert heap/BST/AVL/RB, BFS/DFS, Dijkstra) ทำผิดเพราะ "ข้ามขั้น" จับโจทย์วาดต้นไม้/ตารางไปทีละค่า แล้วเช็คเงื่อนไขทุกครั้ง (เช่น หลัง insert AVL ต้องเช็ค balance factor ทุก node บนเส้นทาง)
ข้อเทียบ complexity — จำ "คู่ตรงข้าม"Quick sort เร็วแต่ worst O(n²) ↔ Merge sort ทนแต่กิน memory O(n) · AVL ค้นไว (สูงไม่เกิน 1.44 log n) ↔ Red-Black แก้ง่าย (หมุน ≤ 2 ครั้งตอน insert) · อย่าลืม Stability: Merge/Insertion/Bubble ได้, Selection/Quick/Heap เสีย
โจทย์เขียนโค้ด — เริ่มจาก skeleton ในสไลด์ข้อสอบมักให้โค้ดครึ่งหนึ่งมาเติม (เช่น /* your code 1 */ ใน BST insert) ฝึกเขียนจากโครงในสไลด์: heap insert/remove, BST delete 3 เคส, Dijkstra lazy queue, Union-Find
อ่านโจทย์ให้ครบ — ระวังคำกุญแจ"min heap หรือ max heap?" · "stable?" · "in-place?" · "directed/undirected?" · "amortized?" คำเดียวเปลี่ยนคำตอบทั้งข้อ เช่น Counting sort จะ stable ต่อเมื่อวางของจากขวาไปซ้าย
เช็คคำตอบด้วย propertyBST → ทุก node ลูกซ้าย < แม่ < ลูกขวา? · Heap → แม่ ≤ ลูกทุกต้น? · RB → root ดำ + แดงไม่ติดกัน + black-height เท่ากันทุกเส้นทาง? · MST → ครบ V จุด, ไม่มีวง, E = V−1 เส้น?
