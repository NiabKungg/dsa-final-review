L08 · Sorting Primer

Sorting — เรียงข้อมูลให้เป็นระเบียบ

บทนี้เป็นบทที่ออกสอบแน่นอนทุกปี — รุ่นพี่เจอทั้ง "trace การเรียงทีละรอบพร้อมผลลัพธ์สุดท้าย" (Bubble, Insertion, Selection, Quick) และ "เติมคำ 15 ข้อเรื่อง Sort/Big-O" เราจะเรียนจากง่ายไปยาก พร้อมภาพไล่ทีละสเต็ปให้เห็นว่าตัวเลขวิ่งยังไง

⭐ ออกสอบ: trace Bubble / Insertion / Selection / Quick ⭐ เติมคำ: stability, Big-O

🤔 ทำไมต้องเรียงข้อมูล (Reasons for Sorting)

ลองนึกภาพหนังสือในห้องสมุดที่วางเล่มสุ่ม ๆ — จะหาเล่มชื่อ "Zebra" ต้องไล่หาทุกชั้น แต่ถ้าเรียงตามตัวอักษรแล้ว เปิดตรงกลาง ดูว่า Z อยู่ครึ่งหลัง เปิดซ้ำไปเรื่อย ๆ ก็เจอในไม่กี่ครั้ง การเรียงลำดับจึงเป็น "การวางรากฐาน" ให้งานอื่นง่ายขึ้น 3 อย่าง (ตามสไลด์):

  • ค้นหา (lookup/search) เร็วขึ้น — ข้อมูลเรียงแล้ว binary search ใช้ O(log n) แทนที่จะไล่หา O(n)
  • รวมชุดข้อมูล (merge) ง่ายขึ้น — สองกองเรียงแล้ว ตักตัวเล็กสุดทีละกองมารวมได้ในเส้นเดียว
  • ประมวลผลตามลำดับที่กำหนดได้ — เช่น รายงานเรียงตามวันที่, จ่ายเงินตามลำดับความสำคัญ

🧱 พื้นฐานที่ต้องรู้ก่อน (อ่านตรงนี้ให้ครบก่อน — ออกเติมคำบ่อย)

📗พื้นฐาน 1: Big-O ใน 2 นาที

Big-O บอก "เวลาโตแบบไหน เมื่อข้อมูล (n) เยอะขึ้น" — เทียบกับการหาคนในห้อง:

  • O(1) — ชี้หาเพื่อนที่นั่งที่โต๊ะ fix ไว้แล้ว 1 ครั้งจบ ไม่ว่าห้องจะมีกี่คน
  • O(log n) — เล่นเกมทายเลข 1–1000 โดยถาม "มากกว่า 500 ไหม?" ตัดครึ่งทิ้งทีละรอบ → 1000 คนก็ใช้แค่ ~10 คำถาม
  • O(n) — ไล่มองทุกคนในห้อง 1 รอบ คนเยอะขึ้นเท่าไร งานเยอะขึ้นเท่ากัน
  • O(n²) — ทุกคนต้องจับมือกับทุกคน คนเป็น 2 เท่า จับมือเป็น 4 เท่า (10 คน=45 ครั้ง, 100 คน=4,950 ครั้ง!)
  • O(n log n) — จุดคานงามของการ sort แบบเปรียบเทียบ (เดี๋ยวอธิบายว่าทำไมต่ำกว่านี้ไม่ได้)

Best case = ดวงดีสุด (ข้อมูลดีไปหมด), Worst case = ดวงซวยสุด, Average case = เฉลี่ยทั่วไป

📗พื้นฐาน 2: ศัพท์ 4 คำที่ข้อสอบชอบถาม
  • Comparison-based sort = เรียงโดย "เปรียบเทียบ" คู่ข้อมูล (ถามว่า ตัวไหนมากกว่า?) ตระกูลนี้ ต่ำสุดที่เป็นไปได้คือ O(n log n) เพราะต้องเทียบอย่างน้อย log n รอบ × จัดการ n ตัว
  • In-place = ไม่ต้องใช้หน่วยความจำเพิ่ม (extra memory เท่ากับ O(1)) เรียง "ในที่" เดิม เหมือนเรียงไพ่ในมือโดยไม่ต้องเอาลงโต๊ะ
  • Stable sort (เรียงแบบเสถียร) = ข้อมูลที่มีค่า key เท่ากัน คงลำดับเดิมไว้ ไม่สลับกัน
    เปรียบเทียบ: แถวคิวชำระเงินที่คนน้ำหนักซองเท่ากัน — ถ้า stable คนที่มาก่อนก็จ่ายก่อน ถ้าไม่ stable อาจถูกสลับ!
    ใช้จริงตอน "เรียงหลาย key": เรียงตามชื่อก่อน แล้วเรียงตามคะแนนด้วย stable sort → คนคะแนนเท่ากันจะยังเรียงตามชื่อให้อัตโนมัติ
  • Internal sort = เรียงข้อมูลทั้งหมดในหน่วยความจำหลัก ไม่ต้องอ่าน/เขียนดิสก์เพิ่ม
⚠️กับดักข้อสอบเรื่องทิศทาง

Ascending = น้อย → มาก (1,2,3…), Descending = มาก → น้อย (9,8,7…) — อ่านโจทย์ให้ดีก่อน trace ทุกครั้ง!

🫧 Bubble Sort — ฟองสบู่ลอยขึ้น

ไอเดีย: ยืนตรวจแถวคิวจากซ้ายไปขวา มองคู่ข้าง ๆ ทีละคู่ ถ้าตัวซ้าย > ตัวขวาก็สลับ (swap) เดินครบแถว 1 รอบ (1 pass) ค่า "หนักสุด" จะถูกดันไปสุดท้ายแล้วอยู่ตรงนั้นตลอด — เหมือนฟองอากาศในน้ำที่ลอยขึ้นเกาะผิวน้ำทีละฟอง

💡เปรียบเทียบ

เหมือนเดินตรวจแถวนักเรียนที่เรียงตามส่วนสูง: มองคนริม 2 คน ถ้าตัวเล็กยืนขวาก็สลับ แล้วขยับไปมองคู่ถัดไป เดินจนสุดแถว 1 รอบ = คนตัวสูงสุดไปยืนท้ายแถวแล้ว รอบหน้าไม่ต้องตรวจท้ายสุดอีก (จึงลดช่วง j < n-i-1)

ทำไมโค้ดวนซ้ำแบบนี้

void bubbleSort(int[] a, int n) {
    for (int i = 0; i < n-1; i++)        // รอบนอก: n-1 pass
        for (int j = 0; j < n-i-1; j++)  // รอบใน: เทียบคู่ข้าง ๆ จนก่อนโซนที่เรียงแล้ว
            if (a[j] > a[j+1])           // ซ้ายมากกว่าขวา → สลับ
                swap(a, j, j+1);
}

สังเกต 2 จุด: (1) รอบนอกแค่ n-1 pass เพราะเหลือตัวเดียวไม่ต้องเรียง (2) รอบในสั้นลงเรื่อย ๆ (n-i-1) เพราะท้ายแถวเริ่ม "นิ่ง" เป็นโซนที่เรียงเสร็จแล้ว

Trace — ข้อมูล [7, 3, 9, 1, 5, 8, 2, 6] (Ascending · 8 ตัว)

💡Improved bubble sort (เวอร์ชันฉลาดขึ้น)

ถ้ารอบไหน ไม่มีการสลับเลยแม้แต่ครั้งเดียว แปลว่าเรียงเสร็จแล้ว — ใช้ตัวแปร swapped จำไว้แล้ว break ออก นี่คือเหตุผลที่ best case เป็น O(n) (ข้อมูลเรียงมาแล้ว แวะดูรอบเดียวจบ) — ส่วนแบบ naïve ที่วนตามโค้ดข้างบน best = O(n²) เหมือนกันหมด

🎯 Selection Sort — เลือกตัวเล็กสุดมาวางหน้า

ไอเดีย: มองทั้งแถว หาตัวเล็กสุด แล้วเอามาสลับไว้หัวแถว จากนั้นก็มองแถวที่เหลือ หาเล็กสุดมาไว้ตำแหน่งที่ 2 … ไล่ไปเรื่อย ๆ เหมือนเลือกกัปตันทีม: จับฉ่ายทั้งห้อง หยิบเก่งสุดคนแรก แล้วไล่เลือกลำดับถัดไปจากคนที่เหลือ

จุดสังเกตสำคัญ (ออกเติมคำบ่อย)

  • จำนวนเทียบ "ตายตัว" ที่ O(n²) เสมอ ไม่ว่าข้อมูลเรียงมาแล้วหรือยัง — เพราะมันต้อง "สแกนหา min" ทุกรอบเสมอ → Best = Worst = O(n²) ในการเทียบ
  • แต่ swap น้อยมาก (สูงสุด n-1 ครั้ง) — จุดขายตัวเดียวของมัน: เหมาะเมื่อ "การเขียนข้อมูลแพง" (เช่น เขียน flash memory)
  • Stable: No! กับดักคลาสสิก — การ "สลับข้ามระยะไกล" อาจกระโดดข้ามตัวที่ค่าเท่ากันไป เช่น [3a, 3b, 1] → รอบแรกสลับ 3a กับ 1 ได้ [1, 3b, 3a] → 3a กับ 3b สลับที่กัน ลำดับเดิมพัง

🃏 Insertion Sort — เรียงไพ่ในมือ

ไอเดีย: ฝั่งซ้ายคือ "ไพ่ในมือ" (เรียงแล้ว) ฝั่งขวาคือกองกองใหม่ หยิบทีละใบ แล้ว สอด เข้าตำแหน่งที่ถูกต้องของฝั่งซ้าย โดยเลื่อนไพ่ที่ใหญ่กว่าไปขวาทีละใบ เริ่มจากฝั่งซ้ายมี 1 ใบ (ไพ่ 1 ใบถือว่าเรียงแล้วเสมอ) จนหมดกอง

เทคนิคในโค้ด: "swap" vs "shift" (มีในสไลด์)

  • แบบ swap (ไม่ใช้ตัวแปร key): เทียบแล้วสลับไปเรื่อย ๆ จนหลุดตำแหน่ง — เขียนสั้น แต่ swap 3 ครั้ง = เขียน 3 เท่า
  • แบบ shift (ใช้ตัวแปร key เก็บค่าที่หยิบไว้): เลื่อนตัวที่ใหญ่กว่าไปขวาทีละตัว จนเจอช่องว่างแล้ว "วาง key ลงครั้งเดียว" — เร็วกว่าในทางปฏิบัติ
💡ทำไม insertion sort ยังมีใช้จริง

ข้อมูลน้อย (สัก 10–30 ตัว) หรือข้อมูล "เกือบเรียงแล้ว" มันเร็วมาก (เกือบ O(n)) — อัลกอริทึมจริงจังอย่าง Timsort (Python/Java) และ Introsort (C++ std::sort) ยังเรียก insertion sort มาใช้กับก้อนย่อย ๆ ตอนแบ่งข้อมูลเหลือชิ้นเล็กแล้ว!

📝แนวข้อสอบ: เลือกอัลกอริทึมให้ตรงสถานการณ์

• "ข้อมูลเกือบเรียงแล้ว อยากได้เร็ว + stable" → Insertion sort
• "เขียนข้อมูลแพง (memory write ช้า) อยาก swap น้อยที่สุด" → Selection sort
• "ต้องการ stable + ทน worst case ที่ O(n log n) แน่นอน" → Merge sort (ไม่ใช่ 3 ตัวนี้ — เล็กเกินกว่าจะ O(n log n) ได้)

🪓 Divide & Conquer — แบ่งแล้วครอง (แนวคิดของ Quick/Merge)

สไลด์มีเรื่อง "Food of thought" ที่เข้าใจง่ายมาก: สมมติมี sort โง่ ๆ ชื่อ dullSort แพง O(n²) ถ้าเราแบ่งข้อมูลเป็นสองครึ่ง (ขนาด n/2) เรียงแยกกันแล้วรวมกลับ:

2 × (n/2)² + n = n²/2 + n ≈ ครึ่งหนึ่งของเดิม — "สองครึ่งดีกว่าทั้งก้อน!"

  • Moral 1: สองครึ่งดีกว่าทั้งก้อน (แบ่งเล็กลงงานถูกย่อ)
  • Moral 2: แบ่งยิ่งเยอะยิ่งดี (แบ่งถี่ ๆ จนเล็กมาก งานยิ่งน้อย → ถึงจุด O(n log n))
  • Moral 3: แบ่งไม่สมดุลแล้วไม่ดี — 0.1n กับ 0.9n ยังเหลือ 0.82n² (ดีขึ้นแค่ 18%) → นี่คือต้นเหตุที่ Quick sort เจอ pivot แย่แล้วหน่ายเป็น O(n²)!

⚡ Quick Sort — เลือก pivot มาขั้นครึ่ง

ไอเดีย: เลือกค่าหนึ่งเป็น pivot (เช่น ตัวสุดท้าย) แล้วจัดแถวให้ ตัวที่ < pivot อยู่ซ้ายทั้งหมด, ตัวที่ > pivot อยู่ขวาทั้งหมด (ขั้นตอนนี้เรียก partition) pivot จะลงตำแหน่ง "สุดท้ายของมัน" แล้ว จากนั้นก็ทำ partition ซ้ำกับครึ่งซ้ายและครึ่งขวาแบบ recursive เปรียบเหมือนการจัดแถวคนตามส่วนสูงโดยเลือก "เกณฑ์" คนหนึ่ง — ตัวเตี้ยกว่าเกณฑ์ยืนซ้าย สูงกว่ายืนขวา แล้วจัดแถวย่อยในแต่ละฝั่งต่อ

Partition ทีละสเต็ป (แบบ Lomuto — ใช้ i เป็น "กำแพงโซนเล็ก")

ข้อมูล [7, 3, 9, 1, 5, 8, 2, 6] pivot = 6 (ตัวท้าย) — กฎ: เจอตัว ≤ pivot ให้ขยายกำแพง (i++) แล้วสลับมาไว้หน้ากำแพง · ตัวที่ > pivot ข้าม

โค้ดเต็ม (Java — Lomuto partition ตามรูปข้างบน)

void quickSort(int[] a, int low, int high) {
  if (low >= high) return;                 // เหลือ 0–1 ตัว = จบ
  int p = partition(a, low, high);          // pivot ลง "ตำแหน่งจริง" = p
  quickSort(a, low, p - 1);                 // โซนซ้าย (≤ pivot)
  quickSort(a, p + 1, high);                // โซนขวา (≥ pivot)
}
int partition(int[] a, int low, int high) {
  int pivot = a[high];                      // เลือกตัวท้ายเป็น pivot
  int i = low - 1;                          // "กำแพง" โซนตัวเล็ก
  for (int j = low; j < high; j++) {
    if (a[j] <= pivot) swap(a, ++i, j);     ← หัวใจ: เจอตัวเล็ก ดันมาไว้หน้ากำแพง
  }
  swap(a, i + 1, high);                     // pivot เข้าตำแหน่งจริง
  return i + 1;
}

จุดชี้ขาดคือ pivot

⚠️Worst case ของ Quick sort = pivot แย่

ถ้า pivot ที่เลือกได้เป็น "ตัวเล็กสุดหรือใหญ่สุดเสมอ" (เช่น ข้อมูลเรียงมาแล้วแล้วเลือกตัวท้ายเป็น pivot) การแบ่งจะเอียงสุด ๆ ฝั่งหนึ่งมี n−1 ตัว อีกฝั่ง 0 ตัว → งานโตเป็น O(n²) (นึกถึง Moral 3: unbalanced แล้วแย่)
Pivot ที่ดีที่สุดคือ median (ค่ากลาง) — แต่คำนวณ median ตรง ๆ แพงไป จึงใช้เทคนิคอย่าง random pivot หรือ median-of-three แทน

สรุปสมรรถนะ: Best/Average O(n log n), Worst O(n²), Memory O(log n) (สแตก recursion), Stable No — ในทางปฏิบัติเร็วจริง (cache friendly, ง่าย) จึงเป็นที่นิยมสูงสุดตั้งแต่ 1959 ถึงทุกวันนี้

🧩 Merge Sort — แบ่งจนเล็กสุดแล้ว "รวม" กลับแบบเรียง

ไอเดีย: หักครึ่งไปเรื่อย ๆ จนเหลือชิ้นเดียว (ชิ้นเดียว = เรียงอยู่แล้วโดยนิยาม) แล้วค่อย ๆ รวม (merge) สองกองที่เรียงแล้วให้เป็นกองเดียวที่เรียง — การรวมกองนั้นง่ายมาก: มองหัวสองกอง ตักตัวน้อยกว่าออกไปทีละตัว (O(n))

💡เปรียบเทียบ

เหมือนรวมสองแถวคิวที่เรียงตามส่วนสูงแล้ว: มองหัวแถวทั้งสอง คนตัวเตี้ยกว่าเดินออกไปตั้งแถวใหม่ ทำซ้ำจนหมด — ไม่เคยต้องเทียบข้ามกองย้อนหลังเลย จึงเร็ว

โค้ดจากสไลด์ (ใช้ tmp array แชร์ตัวเดียว — ประหยัด memory)

public void mSort(int[] arr) {
    int[] tmp = new int[arr.length];   // สร้างครั้งเดียว แชร์ทุก recursion
    mSort(arr, tmp, 0, arr.length-1);
}
private void mSort(int[] arr, int[] tmp, int low, int high) {
    if (low >= high) return;              // ชิ้นเดียว = จบ
    int mid = low + ((high - low) >> 1);  // กึ่งกลาง (ห้าม (low+high)/2 แบบเสี่ยง overflow)
    mSort(arr, tmp, low, mid);
    mSort(arr, tmp, mid+1, high);
    merge(arr, tmp, low, mid, high);      // รวมสองครึ่งที่เรียงแล้ว
}
private void merge(int[] arr, int[] tmp, int low, int mid, int high) {
    int i = low, j = mid+1, k = low;
    while (i <= mid && j <= high)
        tmp[k++] = (arr[i] <= arr[j]) ? arr[i++] : arr[j++];  // <= → stable!
    while (i <= mid) tmp[k++] = arr[i++];   // เศษซ้าย
    while (j <= high) tmp[k++] = arr[j++];  // เศษขวา
    for (i = low; i <= high; i++) arr[i] = tmp[i];  // ก๊อปคืนเฉพาะช่วงนี้
}
📗ทำไม stable อยู่ที่เครื่องหมาย <=

ตอนหัวสองกองเท่ากัน ถ้าใช้ <= จะตัก "ของกองซ้าย" (ซึ่งเดิมอยู่หน้ากว่า) ออกก่อน — ลำดับเดิมไม่ถูกพัง ถ้าเผลอใช้ < ตัวเท่ากันจากกองขวาจะหลุดมาก่อน → เสีย stability ทันที (จุดเติมคำชวนออก!)

วิเคราะห์เวลาแบบ recurrence (สไลด์ทำให้ดูเลย)

T(n) = 2T(n/2) + cn (เรียกสองครึ่ง + merge เป็น cn) → แตกออกเป็น log n ชั้น แต่ละชั้นรวมกัน cn → Θ(n log n)

และเพราะไม่สนว่าข้อมูลเป็นยังไง (แบ่งเสมอ ไม่ขึ้นกับค่า) → Best = Average = Worst = O(n log n) หมด ราคาที่ต้องจ่ายคือ memory เพิ่ม O(n) สำหรับ tmp

🔢 Radix Sort — จัดตาม "หลักตัวเลข" ไม่เทียบเลย

ตระกูล non-comparison sort ทะลุขอบ O(n log n) เพราะไม่ถามว่า "ตัวไหนมากกว่า" เลย! Radix sort ใช้ "หลัก" (digit) เป็นถัง: เรียงตามหลักหน่วยก่อน แล้วหลักสิบ แล้วหลักร้อย … จนครบทุกหลัก เหมือนคัดแยกบัตรประชาชนตามเลขท้ายหนึ่งหลัก แล้วไล่ระดับขึ้นไป — เงื่อนไขสำคัญ: การจัดเข้าถังต้อง stable (รอบก่อนจึงไม่ถูกทำลาย)

สรรพคุณ: Best/Worst/Average = O(nd), Memory O(n+d), Stable: Yes — Counting sort (ข้างล่าง) มักถูกใช้เป็น "เครื่องจัดถัง" ของ radix sort

โค้ด (Java — LSD: counting sort ต่อ 1 หลัก)

void radixSort(int[] a) {
  int max = maxOf(a);
  for (int exp = 1; max / exp > 0; exp *= 10)  // หลักหน่วย → สิบ → ร้อย …
    countingSortByDigit(a, exp);                // ← หัวใจ: sort ทีละหลักจากขวา
}
void countingSortByDigit(int[] a, int exp) {   // โครงเดียวกับ counting sort
  int[] count = new int[10];                  // ถังหลัก 0..9
  for (int v : a) count[(v / exp) % 10]++;
  for (int k = 1; k < 10; k++) count[k] += count[k - 1];
  int[] out = new int[a.length];
  for (int i = a.length - 1; i >= 0; i--) {   // ขวา → ซ้าย = stable
    int d = (a[i] / exp) % 10;
    out[--count[d]] = a[i];
  }
  copyBack(out, a);
}

🗳️ Counting Sort — นับความถี่ + prefix sum

ถ้า key เป็นเลขจำนวนเต็มในช่วงแคบ ๆ (เช่น 0–9, 0–100) เราไม่ต้องเทียบเลย: (1) นับว่าแต่ละค่ามีกี่ตัว (2) ทำ prefix sum (รวมสะสม) เพื่อบอก "ตำแหน่งสุดท้าย" ของแต่ละค่าใน output (3) เดิน input จากขวาไปซ้าย วางของลงตำแหน่ง

โค้ด (Java — เวอร์ชัน stable วางจากขวา)

int[] countingSort(int[] a, int m) {      // ค่า key อยู่ในช่วง 0..m
  int[] count = new int[m + 1];
  for (int v : a) count[v]++;             // 1) นับความถี่ทีละค่า
  for (int k = 1; k <= m; k++)            // 2) prefix sum:
    count[k] += count[k - 1];              //    count[v] = "ตำแหน่งท้าย" ของ v
  int[] out = new int[a.length];
  for (int i = a.length - 1; i >= 0; i--) // 3) วางจากขวา → ซ้าย ← บรรทัดนี้ทำให้ stable
    out[--count[a[i]]] = a[i];
  return out;
}
⚠️กับดักคลาสสิก

Counting sort จะ stable ต่อเมื่อวางของจากขวาไปซ้าย! (ใช้ prefix sum เป็น "ตำแหน่งท้าย") — ถ้าเดินจากซ้าย มันก็ยังเรียงถูก แต่เสีย stability และถ้าช่วงค่า (m) กว้างมาก ๆ เช่น 1 ล้าน เทียบกับข้อมูล 100 ตัว → เสียเปล่าโง่ ๆ นั่นแหละที่มัน "เหมาะกับ key ไม่ห่างกันมากกว่าจำนวนข้อมูล"

🪣 Bucket Sort — จัดถังกว้าง ๆ แล้วอ่านทีละถัง

ทำงานคล้าย counting sort แต่ถังหยาบกว่า: โยนของใส่ถังตามช่วงค่า แล้ววิ่งอ่านออกทีละถัง เป็นตัวอย่าง external (non-)comparison sorting ที่ทะลุขอบ O(n log n) ได้ เหมาะกับข้อมูลที่ "กระจายสม่ำเสมอ"

BestWorstMemoryStable
Bucket sortO(n) เมื่อ m = nO(m+n)O(m)Yes

โค้ด (Java — key เป็นจำนวนเต็ม 0..max)

void bucketSort(int[] a, int max) {
  List<Integer>[] bucket = new ArrayList[max + 1];  // ถัง = ช่วงค่า
  for (int v : a) {                           // 1) โยนของลงถังตามค่า ← หัวใจ
    if (bucket[v] == null) bucket[v] = new ArrayList<>();
    bucket[v].add(v);
  }
  int k = 0;
  for (int b = 0; b <= max; b++)              // 2) อ่านออกทีละถัง = เรียงแล้ว
    if (bucket[b] != null)
      for (int v : bucket[b]) a[k++] = v;
}

🐚 Shell Sort — insertion sort ที่กระโดดข้ามไกลได้

insertion sort ช้าเพราะของ "ต้องเดินทีละช่อง" ถ้าตัวที่ควรอยู่ขวาสุดอยู่ซ้ายสุด มันต้องเลื่อน n−1 รอบ Shell sort แก้โดยใช้ gap (h): จัดให้ทุกตัวที่ห่าง h ช่องกันเป็นกลุ่มเรียงก่อน (h-sorted) แล้วค่อย ๆ ลด h ลงจนถึง 1 (รอบสุดท้ายก็คือ insertion sort ธรรมดา แต่ตอนนั้นข้อมูล "เกือบเรียงแล้ว" เลยเร็วมาก)

💡เปรียบเทียบ

เหมือนจัดหนังสือบนชั้นยาว ๆ: รอบแรกจัดหยาบ ๆ ทุก ๆ 4 เล่ม (ขยับข้ามไกล ๆ ให้ใกล้บ้านที่ถูกต้อง) รอบต่อมาจัดละเอียดทุก 2 เล่ม แล้วจบด้วยการจับคู่ข้าง ๆ — เพราะจัดหยาบไปแล้ว งานละเอียดจึงเหลือน้อยมาก

ใช้จริงใน embedded: uClibc, Linux kernel (โค้ดสั้น ไม่ใช้ call stack) และใน bzip2 สำหรับ array สั้น ๆ

โค้ด (Java — insertion sort แบบเว้น gap)

void shellSort(int[] a) {
  for (int gap = a.length / 2; gap > 0; gap /= 2) {  // h: ลดครึ่ง … จบที่ 1
    for (int i = gap; i < a.length; i++) {    // insertion sort รายกลุ่ม
      int key = a[i];
      int j = i;
      while (j >= gap && a[j - gap] > key) {  ← หัวใจ: เลื่อนทีละ gap (ไม่ใช่ทีละ 1)
        a[j] = a[j - gap];
        j -= gap;
      }
      a[j] = key;                             // วาง key ลงช่องว่าง
    }
  }
}

⛰️ Heap Sort & BST Sort — เรียงโดยใช้โครงสร้างข้อมูล

  • Heap sort: ยัดข้อมูลทั้งหมดลง heap แล้วดึงออกทีละตัว (root คือน้อยสุด/มากสุดเสมอ) → ได้เรียงพอดี Best/Worst/Average = O(n log n) หมด, Stable No (รายละเอียดในบท Heap)
  • BST sort: ยัดลง BST แล้ว walk แบบ in-order → ได้เรียง (รายละเอียดในบท BST) — แต่ถ้าต้นไม้เอียงจะโดน O(n²)

💾ต้องจำโค้ด Sort ไหม? — คำตอบจากรีวิว 2 ปีล่าสุด

ไม่ต้องท่องทั้งบรรทัด! จากรีวิว Final 66 และ 67 ข้อสอบ sort เป็นแนว "ให้ตัวเลข → trace ทีละขั้น" ทั้งหมด (Bubble / Insertion / Selection / Quick) — ไม่เคยมีให้เขียนโค้ด sort มาก่อน โค้ดที่ต้องเขียนจริงมีแค่ Binary String (1 ห้ามติดกัน) ปี 67 และ เติม 1 บรรทัด searchIter ปี 66 (รุ่นพี่สรุปว่า "ออกทฤษฎีเกือบหมด มีแลปแค่ข้อเดียว")

แต่ให้จำ "หัวใจ 1–2 บรรทัด" ของแต่ละตัวไว้ (โค้ดเต็มอยู่ในแต่ละหัวข้อด้านบน) เผื่อปีนี้พลิกเป็นเติมโค้ด / เขียน pseudocode:

  • Quick → partition แบบกำแพง i: if (a[j] <= pivot) swap(a, ++i, j) จบด้วย swap(pivot เข้ากลาง)
  • Counting → นับ → prefix sum → วางจากขวาไปซ้าย (บรรทัดนี้ทำให้ stable)
  • Radix → counting sort ต่อ 1 หลัก วน exp = 1, 10, 100, …
  • Bucket → โยนลงถังตามค่า → อ่านออกทีละถัง
  • Shell → insertion sort ที่เดินทีละ gap แล้ว gap /= 2 จนถึง 1

เกร็ด: trace Quick ในข้อสอบมักใช้ pivot ตัวท้าย + แบบ Lomuto (กำแพง i) เหมือนโค้ดข้างบน — ฝึก trace จริงในหน้า แนวข้อสอบ Drill 1 · ข้อสอบไม่ได้ระบุภาษา โจทย์ trace ใช้แค่ตรรกะ ไม่ต้องจำ syntax

วิธีทำให้ได้คะแนนเต็ม

  2. ระบุ pass/รอบที่ทำอยู่ เช่น "Pass 1: เทียบ (5,3) สลับ → …"

  4. Quick sort แสดง pivot ชัด ๆ และผล partition ของแต่ละรอบ (ซ้าย ≤ pivot ≤ ขวา)

ข้อ 2 (เติมคำ): ลองตอบคำถามด้านล่าง กดดูเฉลยได้

1) อัลกอริทึมไหน "ไม่" เป็น stable sort?
✅ Selection sort สลับข้ามระยะไกล อาจพังลำดับของค่าที่เท่ากัน (ส่วน Quick และ Heap ก็ไม่ stable เหมือนกัน — ระวังโจทย์พลิก!)
2) ขอบเขตล่างของ comparison-based sort คือเท่าไร และใครทะลุขอบได้?
✅ การเทียบคู่ต้องเทียบอย่างน้อย log n บิตข้อมูล × n ตัว → O(n log n) แต่ non-comparison sort ไม่ได้ "เทียบ" เลย จึงไปถึง O(n+m) หรือ O(nd) ได้
3) ข้อมูล [2,3,4,5,1] กับ Insertion sort — ต้อง "เลื่อน" กี่ครั้ง?
✅ ตัว 1 ต้องข้าม 2,3,4,5 = เลื่อน 4 ตัว → ตัวเดียววางผิดที่ก็ยังเสีย O(n) เท่าจำนวน inversion — insertion sort นับเวลาจาก "จำนวนคู่ที่สลับตำแหน่งกัน" (inversions) เสมอ
